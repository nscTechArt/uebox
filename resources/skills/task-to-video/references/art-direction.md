# 导演与画面质量

## 先找到这条片的理由

从任务里找一个值得讲述的变化：被解决的问题、意料之外的发现、最终成果的独特之处。
用一句话写清观众看完应该理解或感受到什么，再确定表达方式。不要把工具执行日志顺序当故事。
宣传片可以有情绪和悬念；教程的美感来自清楚的引导和恰当的细节；整活的节奏由包袱决定。

在工程写 `direction.md`，保持短而具体：

- 核心想法：这条片为什么值得看，以及真实依据。
- 视觉母题：从任务主体提取一种可重复、可变化的形状、构图关系或运动。不要凭空堆技术感装饰。
- 艺术方向：字族、字号层级、背景与强调色、材质、画面密度；这些服务于主题，不预设全部黑底或全部卡片。
- 镜头计划：每镜头目的、主要素材、构图、时间段内发生什么、和前后镜头如何连接。
- 声音计划：旁白语气、音乐情绪、需要停顿或强调的位置。无配音也要有视线引导。

## 设计一个镜头，而不是布置一页幻灯片

每镜头写出真实秒数的动作与停留。例如一段 7.2 秒的“比较两次结果”：

1. 0–1.5：旧图占主要区域，先让观众看懂问题；只出现问题标签。
2. 1.5–3.2：保持主体尺度不变，遮罩揭示新图；变化位置高亮一次。
3. 3.2–5.6：讲解具体改善时才出现对应局部和简短标注。
4. 5.6–7.2：收去辅助强调，停留完整结果，准备下一镜头。

这只是编排方法，不是通用模板。镜头可以静止，但静止应让人有东西可看；不要前一秒把全部信息倒出来，再空等旁白。

## 构图与字体

- 每个时刻有明确第一视觉焦点。主体、标题与注释不能同等抢眼。
- 横屏 2K 下，主标题通常 96–220 px，关键说明通常 36–60 px；这是检查可读性的起点，不是硬性样式。
- 先设计文字和主体的关系：压在画面负空间、与主体边缘对齐、作为遮罩或节奏支点。不要一律“上标题下字幕”。
- 根据内容选择满幅、左右对照、局部特写、分层深景或纯文字冲击。连续镜头构图变化必须有叙事理由。
- 原图直接引用 `compositionAssets`；需要裁切时使用内层 `object-fit` / `object-position` 或遮罩。读参数的教程保持真实、清楚，不用美化遮盖操作细节。
- 系列画面保持字体、色彩和运动语法一致；不要每张图换一套审美。明确主题也允许有意的冷暖、明暗反差。

## 动作与声音

- 使用暂停且可寻址的 GSAP 时间轴；运动负责揭示、聚焦、比较或连接。每个元素持续漂浮不是高级感。
- 优先自然的加速、减速和错开揭示；不用每次都是同样的淡入。允许短促冲击后长停留。
- 先锁定旁白实际时长，再把视觉揭示放到相应语句。工具不提供逐字时间戳，不把估算标为精确字幕对齐；需要精确时试听校正。
- 转场在源与目标之间传递一个共同元素或构图关系。全片 HTML 可以编排跨镜头衔接；多个 HTML 之间默认硬切，各自设计出入动作。
- 音乐应承托叙事起伏，而非持续铺满。旁白清楚优先。无法实际试听，就明确声音尚未验收。

## 质量复核与返工

通过 `preview_task_video` 取得真实渲染的多个时间点，用 `read_local_file` 查看每张图。
先审整体：这一组画面是否像同一部作品？是否机械重复？是否有一个鲜明、可信的开场和有余味的结尾？
再看细部：主体是否够大、字体是否合适、对齐和裁切是否干净、每句话是否对应正确画面。
最后播放检查：揭示时机、加减速、镜头衔接、阅读时间、声音是否完整。静态预览无法代替这一项。

发现弱镜头就修该镜头。不要通过提高分辨率、增加粒子、加长时长或换音乐来掩盖构图与叙事问题。
新版本不能仅因工具返回成功就交付；交付时如实说明已检查画面、已播放的部分和仍未验证的项目。
