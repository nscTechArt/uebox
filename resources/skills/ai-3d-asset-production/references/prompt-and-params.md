# 提示词与参数怎么定

生成结果差，八成不是「模型不行」，是输入不行：图不合格、提示词按生图的写法写、
面数按「反正选最高」选。这份文件给的是**可执行的取值依据**，来源列在最后一节。

数字大多来自 Tripo 的公开文档（三家里它把范围写得最细），但前三节的道理三家通用 ——
输入图质量和提示词写法不挑厂商。厂商各自支持哪些参数，回 SKILL.md 读那份能力对照表。

## 1. 输入图的标准

图生 3D 的上限在这张图上。接口只卡两条硬的：**JPEG / PNG、单张不超过 20 MB、
不低于 256×256**。真正决定质量的是下面这些软的：

| 项 | 要求 | 不满足会怎样 |
| --- | --- | --- |
| 分辨率 | 2048×2048 以上 | 低分辨率会出台阶状的锯齿边 |
| 背景 | 透明底 PNG 最好，纯色底次之 | 杂乱背景让算法认错物体边界 |
| 光线 | 均匀漫射，不要强直射、不要背光 | 硬阴影会被读成体积，网格上出现莫名的凹坑和鼓包 |
| 角度 | 前侧 3/4 视角信息量最大 | 俯拍、极端透视、大特写都会让几何变形 |
| 主体 | 单一、不遮挡、不反光、占满画面 | 遮住的结构只能靠猜 |

**这套标准我们自己就能满足** —— 四视图是 `generate_image` 出的，写提示词时直接
把「纯色背景、均匀布光、无阴影、正交视角、物体完整入画」写进去，比生成完再回来
补救便宜得多。用户自己拍的照片不合格时，说清是哪一条不合格，别闷头生成。

## 2. 提示词怎么写

**公式：主体 + 形态 + 材质 + 关键细节 + 风格。** 就这五段，短的比长的好 ——
官方明确说过当前模型是「一个主体 + 简短修饰」表现最好，堆得越长越容易丢细节、
出畸变。接口上限 1024 字符（约 100 词），但那是上限不是目标。

**别写镜头和光线。** `cinematic lighting`、`8k`、`背景虚化`、`逆光` 这些是生图的
词，在 3D 这一端不产生几何，纯属浪费。同理，写「站在草地上」只会让它给你多生一块地台。

```
✗  一个精致的中世纪战斧，电影级光照，8k 超高清，史诗感，背景是燃烧的城堡
✓  中世纪双刃战斧，宽刃、木柄缠皮革，钢面有磨损划痕和缺口，写实风格
```

```
✗  可爱的狗狗小屋，很温馨，阳光洒下来
✓  柯基造型的狗屋，奶油色盒形建筑，蓝色底座和门，屋顶是柯基头（橙耳、白嘴、粉内耳），
   正面有橱窗和骨头形招牌，卡通风格
```

**想去掉的东西写进 `negative_prompt`，不要写进 `prompt`。** 底座、支架、背景板
是生成 3D 最常见的多余物，几个词就够。写成 `negative: base, stand` 塞进正向提示
是没用的 —— 那串字会被当成物体描述读进去。这一位只有绑了 Tripo 时才有（见第 7 节），
没有它的时候就在正向提示里把物体说完整（「单个物体，无底座」）。

## 3. 面数怎么选

工具收的是 `quality` 四档，各家在底下换算成自己的面数上限。**按用途选，不要一律 high**：

| 用途 | 选 | 理由 |
| --- | --- | --- |
| 远景、背景道具、一次性摆件 | `extra-low` / `low` | 看不清细节，面数是纯负担 |
| 可交互道具、手持物 | `medium` | 玩家会走近看，但不是主角 |
| 主角、特写、要拿来做宣传图的 | `high` | 只有这一档值得付高面数的代价 |

两件容易踩的：

- **Tripo 的 H 系列和 P 系列量级差 75 倍。** H 系列（v3.x）是高精度线，
  `high` 档对应十几万面；P 系列（P1）整体压在 20,000 以内，是为低面数干净拓扑
  做的。选 P 系列却期待 H 系列的细节，是在怪错人。官方对 P 系列的建议甚至是
  **从 150 面（简单物体）/ 250 面（复杂物体）起步**往上调。
- **四边面（`topology: 'quad'`）另有上限**，官方建议不超过 150,000。它的用途是
  「还要进 DCC 继续改」，直接进引擎用三角面就行。注意 Tripo 的四边面只能导 fbx。

## 4. 多视图怎么给

顺序就是朝向：**`正面 → 左 → 背 → 右`**，工具按数组顺序往视位里放。

- **给 2 张时，它们被当成「正面 + 左」。** 所以手上只有正面和背面时，不要只传这两张 ——
  传上去会得到一个「左侧看起来像背面」的模型，而且**不报错**。这种情况要么补齐四视图，
  要么就只传正面那一张。
- **正面那张不能省**，官方也不建议只给一张以外的少于两张的组合。
- 上限四张（Rodin 除外，它不卡张数）。第五张会明确报错。
- 四视图之间怎么保证是同一个东西，回 SKILL.md 读那份四视图一致性说明。

## 5. 种子怎么用

`seed` 固定的意义是**锁住几何**：同一组参数配同一个种子，出来的是同一个造型。
用法是「造型对了，只想换材质说法或者微调细节」时带上上一次的种子 ——
不带的话每次都是一个新造型，你在拿两个不同的东西比好坏。

反过来，造型本身就不对时**换种子**，别在原地改词。

## 6. 不满意时怎么迭代

- **一次只改一个变量。** 同时改提示词、精度和参考图，出来变好变坏都不知道是谁的功劳。
- **比几何，不比好看。** 拿到 2–4 个候选时，先看轮廓、比例、结构对不对，
  再谈观感 —— 观感在贴图那一步还能救，几何不能。
- **对着原始参考图逐条验，不要跟自己的上一版比。**「比上一版好」和「符合要求」是两件事。
- **同一个缺陷连续三次没修好就停下换方法**，别试第四次。这时候该怀疑的是输入
  （缺视图、缺尺寸说明）或者路线（该重拓扑的在调参数）。
- 每一次生成都是一次真实扣费，重做前先问用户。

## 7. 入参表会随绑定的厂商变

`generate_3d_model` 的入参表**不是固定的**：用户给「3D 生成」绑了 Tripo 时，
会多出一组只有它有的开关；绑别家时那一组根本不出现。所以判断有没有某个参数，
看这次调用时工具入参表里有没有，不要照着记忆写。

绑了 Tripo 时多出来的那组，按用途挑，**每一个都额外花钱，不要一次全打开**：

| 想解决的问题 | 用 | 代价 |
| --- | --- | --- |
| 出来的东西带底座、支架、背景板 | `negative_prompt` | 不额外花钱，最划算 |
| 要游戏资产、在意拓扑 | `smart_low_poly` | 约 +10；面数会被压进 1000–20000（配四边面 500–10000） |
| 整批资产尺寸要一致 | `auto_size` | 不额外花钱。Tripo 没有 `bounding_box`，这是它这边的替代 |
| 进引擎后要一个个转朝向 | `align_orientation`（要有参考图） | 不额外花钱 |
| 主角、特写要更细 | `geometry_quality` / `texture_quality` 的 `detailed` | 约 +20 / +10，只给主角开 |
| 用户给的是随手拍的照片 | `image_autofix`（要有参考图） | 更慢 |
| 要分件而不是一整块 | `generate_parts` | 约 +20，**出来没有贴图**，且与 `material`、四边面互斥 |

系列差别：`smart_low_poly`、`geometry_quality`、`generate_parts` 和三个对齐类开关
**只有 H 系列（v3.x）有**；`texture_quality: extreme` 反过来只有 P 系列有。
选错会明确报错，不会静默生效。

入参表里没有的开关，把名字写进 `prompt` 不会激活任何东西，只会污染物体描述。
用户点名要一个当前没有的开关时，如实说这一版没有这一位。
