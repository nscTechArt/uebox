# 连接虚幻引擎

正常情况下你什么都不用做：导入工程时插件自动装好，编辑器一开就自己连上。

这页是给不正常的情况准备的 —— 连不上、装不上、不想让它装。

助手查关卡、改属性、跑 PIE，靠的是一个装在你工程里的插件：**UnrealAgentLink**。没有它，助手够不着引擎，只能聊天。

## 它怎么装上的

**默认全自动。** 装的位置是 `<工程>/Plugins/UnrealAgentLink/`，**不是引擎目录**。

一次安装做四件事：

1. 把对应引擎版本的插件解压到工程的 `Plugins/UnrealAgentLink/`
2. 清掉同一引擎下早期版本留在引擎目录里的残留
3. 往 `.uproject` 的插件列表里加上它并置为启用
4. 往 `.gitignore` / `.p4ignore` 各加一行 `Plugins/UnrealAgentLink/`

::: tip 第 4 步是为了不把它提交进版本库
插件是盒子装的，不是你工程的一部分，也会随盒子升级换版本。忽略掉它，团队里没装盒子的人不会被这个目录干扰。
:::

触发时机有两个：**导入工程时**，以及**每次启动应用时**遍历已导入的工程，版本落后就静默升级。

支持 **UE 5.0 到 5.8**，正式安装包里九个版本的插件都在。

::: tip 为什么正式包坚持要九份
发版时少一个版本，那个版本的用户就实实在在装到旧插件。所以打正式包的门禁要求 5.0–5.8 全部存在且与源码一致。
:::

### 为什么装到工程而不是引擎

三条实际原因，不是风格偏好：

| 原因                 | 具体是什么                                                                       |
| -------------------- | -------------------------------------------------------------------------------- |
| **权限**             | Launcher 装的引擎在 `C:\Program Files` 下，非管理员写不进去；工程目录永远可写    |
| **构建缓存**         | 引擎目录下的插件会被编进引擎级的构建规则缓存，反复装卸容易把它搅浑，报错难以归因 |
| **没有版本匹配机制** | Epic 自家插件敢装引擎级，是因为 Launcher 会按你的引擎版本推送对应构建            |

### 随包带的是源码 + 预编译

带二进制是为了不要求你自己编译；**同时带源码**是为了自编译引擎能用 —— 自编译引擎每次编译的构建标识都不同，永远对不上预编译的二进制，带着源码引擎才能在对不上时当场重编一遍，你这边无感。

插件源码在仓库的 `plugin/UnrealAgentLink`，用的是独立的 **MIT 许可证**，想自己编就自己编。

## 不想让它自动装

**设置 → 插件 → 关掉「自动安装连接插件」。**

单个工程不想要：工程卡片右键 → **移除 UnrealAgentLink**。这会删掉那个工程下的 `Plugins/UnrealAgentLink` 目录、从 `.uproject` 里摘掉它，并把这个工程记进一份**不再自动安装**的名单。

::: tip 这份名单解决的是一个真实投诉
「UnrealAgentLink 怎么删？每次删了盒子打开项目又出现了。」

早先手删插件目录没用 —— 代码把「文件不存在」一律理解成「需要安装」，下次打开工程就原样装回来。现在从右键菜单移除才算数：名单一记，上面那两个触发时机一起失效。

想装回来就右键 →「安装 UnrealAgentLink」，它会先把这个工程移出名单。
:::

## 确认连上了

**设置 → 插件 → 连接状态**：

![设置 → 插件：连接状态](/shots/settings-plugin.png)

| 显示             | 含义                                |
| ---------------- | ----------------------------------- |
| 引擎桥接：正常   | 应用已在端口 `17860` 上等待引擎接入 |
| 引擎桥接：未运行 | 桥接没运行，引擎连不进来            |
| 引擎桥接：读取中 | 还在问状态                          |
| 已连接的工程：N  | 当前有 N 个编辑器接上了             |

::: tip 不需要手动连接
插件会自己连过来，断了每 5 秒重试一次。

![连上之后：引擎桥接「正常」，已连接的工程为 1](/shots/settings-plugin-connected.png)

**工程明明开着，「已连接的工程」却一直是 0** —— 最常见的原因是那个工程根本没装插件。回项目库，工程卡片右键 →「安装 UnrealAgentLink」。
:::

状态尚未读取到时显示「正在读取桥接状态…」，而不是「未运行」。

桥接真的起不来时，主界面会挂一条横幅：「引擎桥接没能启动」。

## 常见情况

### 导入工程时提示插件没装上

提示里会写原因：

| 原因                          | 处理                                                                                 |
| ----------------------------- | ------------------------------------------------------------------------------------ |
| 这个 `.uproject` 没写引擎版本 | 缺 `EngineAssociation`。用 UE 正常打开一次工程通常会补上，也可以手动编辑 `.uproject` |
| 没有这个引擎版本的随包插件    | 引擎版本超出 5.0–5.8，或者你用的是自己构建的精简包                                   |
| 这个 `.uproject` 读不出来     | 文件可能已损坏，先确认它是完整的 JSON                                                |

弹窗的主按钮是「**让 AI 看看**」—— 点它会新开一条会话，把工程路径和失败原因直接交给助手去查。也可以事后从工程卡片右键手动安装。

### 应用更新后，一批工程提示插件没能更新

应用一升级，所有工程的插件同时判过期，失败往往是一批。它们还在用旧版插件，多数时候照常能用，但建议重装。

::: warning 重装前先关掉虚幻编辑器
文件被占用是头号失败原因。
:::

::: tip 「要不要重装」不只看版本号
判据是两条都满足才算最新：版本号不低于随包版本，**而且**源码指纹一致。

只比版本号会漏掉最常见的一种情况 —— 插件源码改了但版本号没跟着动。那样的话装过某个版本的用户永远拿不到后来重编的同一个版本号，修好的东西发不出去。

所以有时版本号看起来没变，它照样会提示更新，这是对的。
:::

### 装不上时不会写进 `.uproject`

安装失败时，`.uproject` 里不会留下指向它的条目。

这是有意的：留个坏条目的话，UE 启动时会报「找不到插件 X」并弹框问要不要禁用，生成工程文件或构建时直接失败 —— 你什么都没做就先撞上一个错误。装不上就当没发生过。

同理，右键手动安装在报「成功」之前会回读一次插件文件是不是真的在磁盘上。

### 清理旧版插件

早期版本会把插件装到**引擎目录**里。**设置 → 插件 → 清理旧版插件** 可以清掉这些残留。

同样需要**先关闭虚幻编辑器**，否则文件被占用会导致失败。提示会列出未能清理的引擎。

清理完会报「已清理 N 个引擎的残留插件」，一个都没有时报「未发现残留 UnrealAgentLink 插件」。

## 插件源码

设置 → 插件 → 「插件开源项目」可以打开源码地址，看代码和更新记录。

## UE 5.8 的额外能力

工程用 UE 5.8 或更高版本时，应用还会自动接入引擎官方的 MCP 工具集，见 [MCP · 虚幻引擎自带的工具集](/guide/mcp#虚幻引擎自带的工具集)。该工具集与 UnrealAgentLink 相互独立，可同时使用。
