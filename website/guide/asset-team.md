# 资产库：团队协作

一个资产库多人共用。新建资产库时选「网络协作库」即可 —— 这一项默认就是开的，不需要先去设置里打开（真要关掉它，开关在 **设置 → 资产库 → 高级**）。

两种接入方式，按团队规模选。

![新建资产库 → 网络协作库：SMB 共享与资产服务器两个页签](/shots/vault-create-network.png)

## SMB 共享

人少或者临时用的做法，不需要部署服务端。

一台机器当主机，其他人填一个共享路径连上去，例如 `\\192.168.1.100\Assets`。新建资产库 → 网络协作库 →「SMB 共享」。

填写路径后应用会检测一次，结果分五种：

| 提示                   | 含义                 |
| ---------------------- | -------------------- |
| 路径可访问，有写入权限 | 能读能写             |
| 路径可访问（只读）     | 只能看               |
| 需要认证               | 要填凭据，见下       |
| 路径无法访问           | 路径或网络有问题     |
| 检测失败               | 检测这一步本身没跑成 |

### 网络认证

需要认证时会弹「网络认证」：用户名（`域\用户名` 或 `用户名`）和密码。勾「记住凭据」会**加密保存在本地**。

### 主机访问码

主机那台机器在保管库设置里能看到两个码：

- **浏览码（只读）**
- **管理码（可写）**

把码发给同事，他们在连接时填上就能用。

也可以勾「**允许共享目录里的同事写入**」—— 勾了之后，能访问这个共享文件夹的电脑自动获得写权限，不用手动填码。

::: warning 重新生成会让所有人掉线
「重新生成」之后，所有用旧码连接的电脑都会掉线，需要重新填码。
:::

填错码时的提示是「资产库访问码不正确，请向主机确认」；没填是「需要资产库访问码，请向主机索取配对码后填写」。

## 资产服务器

管理员在 NAS 或常驻运行的机器上部署服务端，成员使用服务端地址和账号连接。

新建资产库 → 网络协作库 → 「**资产服务器**」：

1. **填地址** —— IP 和端口
2. **登录** —— 普通成员用**成员账号**，管理员用**节点 KEY**
3. **选库** —— 服务器上已有的资产库会列出来，点一个就进去。有权限的话也能在这里直接新建

高级选项里可以填**管理员 KEY** 和**共享浏览路径**：

- 没有 KEY 时只能浏览，有 KEY 才能上传/覆盖
- 共享浏览路径只用于「打开本地路径 / 定位文件」，建议填一个可访问的 SMB 共享路径

服务端的资产库按「**资产路径**」分组，一个库归到哪个分组随时能调，**只改归属，不动文件**。管理端的操作见[资产节点管理](/guide/asset-server)。

### 权限默认是只读

服务器**默认给只读**：能浏览、能下载、能看缩略图，但传不上去也覆盖不了。

开放写权限有三种方式，由管理员选择：分配可写的成员角色、提供管理员 KEY、或在服务器上按 IP 单独放开。

::: warning 没有写权限时上传按钮不是灰的
按钮可以点，**错误在上传的时候才返回**。传不上去先确认自己是不是只读身份。
:::

成员分「成员」和「节点管理员」两级。节点管理员能加人、建库、删库；普通成员只管用。

## 同步

### 实时推送

连接期间通过长连接实时推送：其他成员上传资产、修改标签、移动文件夹后，本地列表自动更新，不需要手动刷新。

工具栏上还有两个手动动作：

- **拉取同步** —— 从服务器拉取最新变更
- **扫描变更** —— 扫描服务器上的文件变更

### 断网时

改动记在本地排队，界面上会写出来：

| 提示                                                 | 含义               |
| ---------------------------------------------------- | ------------------ |
| 已保存到本地，但未连接到资产服务器，N 条改动待同步   | 断线了，排着       |
| 已保存到本地，但推送到资产服务器失败，N 条改动待同步 | 连着但推送失败     |
| 有改动无法同步到资产服务器，请检查冲突               | 卡在冲突上了，见下 |

网一通会自动推上去。离线几小时也补得回来。

主机离线时页面上会显示「主机离线」和「重试连接」。

## 版本冲突

多人修改同一份索引时弹出「**版本冲突**」，显示双方的版本、修改者和修改时间，需二选一：

| 选择             | 后果                                         |
| ---------------- | -------------------------------------------- |
| **使用远程版本** | 放弃本地未同步的修改，用服务器上的最新版本   |
| **覆盖远程版本** | 用本地版本覆盖服务器，**其他人的修改将丢失** |

选覆盖时弹窗会再提示一次「此操作将覆盖远程修改，请确认您了解风险」。

## 删除的差别

在网络协作库里删东西和在本地库里不是一回事：

| 操作         | 本地库                 | 网络协作库                                           |
| ------------ | ---------------------- | ---------------------------------------------------- |
| 删文件夹     | 进「最近删除」，可恢复 | **共享盘上的目录一并删除，全队失去，无法恢复**       |
| 删保管库本身 | 永久删除文件和数据库   | 只移除本地连接记录和缓存，**不动网络位置上的源文件** |

## 缓存

网络库的缩略图会缓存在本地。保管库菜单里的「清除缓存并重新加载」可以清掉，会报清了多少张、释放了多少 MB。

缺少写入权限时清不了，会明说「网络库缺少写入权限，无法清理缓存」。

## 传得慢

上传耗时主要按**文件个数**付固定开销，不是按总体积。文件多而碎的时候尤其明显。

工程这种成千上万个小文件的情况，用[工程整包](/guide/asset-to-project#工程整包)走打包传输，比逐个文件快得多。
