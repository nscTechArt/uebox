# 语音通话

用语音代替打字与助手交互。

语音层的分工是**前台与后厨**：语音模型负责听、说、分诊、报进度；真正动工程的活交给 AI 会话那套 Agent 去做。这条分工决定了下面几乎所有行为。

## 配置

**设置 → 模型 → 默认模型 → 实时语音**。

支持 OpenAI 的 `gpt-realtime` 系列和豆包 Seeduplex。普通对话模型不适用于这个接口。

音色在「模型」页面设置，修改后下次通话生效，当前通话不会中途更换。

**语音合成（TTS）** 是另一项能力，用于朗读助手的文字回复，走单独的默认模型。两者可以只配置其中一个。

### 麦克风

**设置 → 语音 → 麦克风**。默认使用系统设备，也可以指定一个。修改后下次通话生效。

![设置 → 语音](/shots/settings-voice.png)

提示「无法读取麦克风，请检查设备和权限」时，通常是系统层面未授予麦克风权限。

## 开始一通电话

入口是输入框上的麦克风按钮（「开始语音对话」）。从哪里点，决定了这通电话绑在哪条对话上：

| 从哪里开口         | 绑在哪                                     |
| ------------------ | ------------------------------------------ |
| 欢迎页             | 就地绑住眼前这条空对话，每次都是独立的一段 |
| 某条已有对话里     | 绑住这条：上文读它、对白写它               |
| 通话中点另一条的麦 | 不换绑，维持当前这通                       |

通话里说的第一句话会顺手给这条对话起个名字（标题还是占位符时才改）。

连接过程中输入框显示「正在连接语音…」，可以「取消连接」。超时时提示「语音连接超时，请重试或检查实时语音模型设置」。

::: tip 通话是应用级的，不跟着页面走
切会话、切标签页、去资产库都不会断线，回来接着说。只有你主动挂断才结束 —— 或者清空这通电话绑的那条对话。
:::

## 它自己答什么，派给谁

**只读的快查它当场答**：列已登记的工程、列可以派活的对话、看现在连着哪个编辑器、看一眼编辑器里选中了什么。这些不进 Agent，因为权限、确认、撤销栈保护的是「写」，对只读查询它们只贡献一两秒延迟。

**任何会改工程的事都派给后台 Agent**，而且**派完就返回**，不等执行结果。所以你听到「开始做了」之后可以接着跟它说话，它不会卡在那儿等。

::: warning 「开始做了」不是「做完了」
派发的回执只是一句「已收到」。真正的结果会在做完时另外念给你听。
:::

### 说不清名字的时候

说「把这个调暗一点」而没给名字时，它会先看一眼编辑器，把名字说出来跟你确认，再按名字派活 —— 而不是直接猜一个去改。

## 几件活同时跑

每件活会被分到一个**灶**（一个短名字，说清这件活动的是哪个东西）。规则只有一条：**会不会动到别的灶正在动的那个东西**。

| 情况                     | 结果                                     |
| ------------------------ | ---------------------------------------- |
| 动的是两个不同的东西     | 各占一个灶，**真正同时跑**               |
| 可能动到别人正在动的东西 | 排在那个灶后面，告诉你「排在第 N 位」    |
| 接着改同一个东西         | 落到同一个灶，那条会话记得上一件做过什么 |
| 灶开满 5 个还要再派      | 排到最久没用的那个灶后面，并照实说       |

几件同时跑时：

- 某一件做完了，念出来时会带上灶名（「灯光那边，……」）
- 你问「做得怎么样了」，它报所有灶的全貌，不是最近那一件
- 你说「停下」，它**不猜**要停哪件，先问你

::: tip 派活会另开一条任务对话
这通电话**第一次派活**时会建一条配套的对话「语音任务 · 这通的名字」，执行过程和结果都落在那里。没派活就不建。
:::

## 说话之间

### 打断

默认全双工 —— 它说话时麦克风不关，**你直接开口就会打断它**。立刻停、丢掉在途的残片，**任务不停**。

不方便出声时：点界面上的球体，或在 设置 → 快捷键 →「打断语音助手」绑一个按键。

::: warning 什么时候会退化成半双工
两种情况下麦克风会被强制静音，此时只能靠快捷键或点球体打断：

- 本地朗读一条兜底通知时（这条路径不经过回声消除）
- 建立回声消除通路失败时（`RTCPeerConnection` 不可用或被拦截）

:::

外放时它听见自己的声音会被当场消掉（播放走 WebRTC 回环），不会自己跟自己聊起来。

### 改主意和喊停

| 你说的            | 会发生什么                                       |
| ----------------- | ------------------------------------------------ |
| 「等等，改成 XX」 | 插进正在跑的那一轮，不新开一件                   |
| 「停下」          | 停正在跑的那件，队里还没开始的一起撤掉，并说出来 |
| 「算了别做那件」  | 从队里撤掉，不播报                               |
| 「不用了，再见」  | 道别那句念完自动挂断；你又开口就不挂了           |

::: tip 还有活在跑时说「再见」
它会先说清在跑什么再问你。你坚持才挂断 —— 活照样在后台跑完，下次开语音会告诉你结果。
:::

### 暂停收音

输入框上有「暂停收音」，暂停期间**后台任务继续运行**。结束整通电话是另一个按钮（「结束语音对话」），任务同样继续跑。

## 反问与审批走语音

Agent 需要你拍板时，语音会把问题念出来：

- **它问你选哪个** —— 口头回答就行，原话交回去；说「你看着办」就让它自己定
- **它要审批一次高风险操作** —— 口头表态。**它绝不会替你批准**；你含糊其辞或它没听清，一律按拒绝处理
- **你没等它念完，直接在界面上点了答案** —— 语音那条作废，不再念，任务继续

::: warning 审批这道确认拦的是「听错一句就删了场景」
所以「以后都行」这类长期授权只在你明确说出口时才会给出去。
:::

## 挂断再接上

任务不受语音影响 —— 挂断时照跑。再开语音时它会先把你不在期间的事交代一遍：

| 不在线期间发生的         | 接上时                                 |
| ------------------------ | -------------------------------------- |
| 活做完了、失败了、卡住了 | 先念这些（同一件活同一类只留最新一条） |
| 反问或审批还没人答       | 再念一遍                               |
| 反问在界面上已被答掉     | 作废，不念                             |
| 还在跑的活               | 提一句最近一次汇报                     |
| 中途进度                 | 丢掉，那是过去式                       |

一条都没有就一个字不说。

关掉语音时队里还排着活，下次开语音会自动接着跑。

## 自动朗读

**设置 → 语音 → 自动播放**：AI 会话生成结束后自动朗读回复。需要先配置「语音合成」模型。

单条回复也可以手动点朗读按钮。

## 汇报多少

**设置 → 语音 → 助手反馈**：

- **简洁** —— 只响应提问，不主动汇报进度
- **详细** —— 长任务无反馈满一分钟时汇报进度

**无人回应时自动结束通话** —— 空闲时连续三次无人回应则挂断。

## 边界

- **语音层不做多步规划，也不直接执行写操作。** 规划、工具权限、确认、撤销栈全在 Agent 那一侧，语音绕不过去。
- **能当场答的只有白名单里的只读查询**，新增一项要显式加进去，默认不在里面。
- **助手页全关掉时派不了活**，它会照实说「先打开助手页」。
- 语音念出去的每一句，都会出现在这通电话绑的那条对话里 —— 不存在只说不留痕的话。
