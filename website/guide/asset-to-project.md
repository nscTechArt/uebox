# 资产库：导入到 UE 工程

把库里的素材送进虚幻工程。

## 基本流程

选中资产或文件夹 → 右键「**导入项目**」→ 选目标工程 → 「开始导入」。

文件夹会连同其中的资产一起导入。弹窗标题标明本次导入的内容：「导入 N 项，文件夹连里面的资产一起」「导入文件夹：某某（N 个资产）」。

## 目标工程要开着

弹窗里列出已注册的工程，可以按名称/路径搜索，也可以按 UE 版本筛选，还能「添加工程」。

没连上的工程会标出来：「**这个工程没连上，先在 UE 里打开它。**」

## 导入前的版本检查

选好工程后会先做一次版本预检，结果有三种：

| 显示                                           | 含义                   |
| ---------------------------------------------- | ---------------------- |
| 没发现版本冲突                                 | 可以直接导             |
| N 项要求更高版本的引擎，开始导入时会问你怎么办 | 有冲突，待会儿要做选择 |
| 版本没检查成                                   | 预检本身失败了         |

另有一条固定提示：**外部文件、插件和压缩包能不能用，要看内容和目标引擎**。这几类无法仅通过文件头判断。

### 有资产版本太高

弹窗会写明：目标工程是 UE X，这 N 项要更高版本，并列出是哪几个（多了会折成「…，等 N 项」）。三个选择：

- **换个工程** —— 找一个版本够高的
- **只导其余的** —— 跳过这几项
- **仍然导入** / **仍然全部导入** —— 原样复制文件，**不做版本转换，UE 里多半打不开**

## 压缩包

导入压缩包时会问一次怎么处理：

| 选择           | 结果                                         |
| -------------- | -------------------------------------------- |
| **解压后导入** | 内容解到工程的 `Content` 里，UE 里直接能看到 |
| **原样复制**   | 压缩包放入 `Content/Imported`，需自行解压    |

可以勾「以后都这么处理」。也可以在 **设置 → 资产库 → 压缩包导入前询问** 里关掉这个询问，关掉后一律解压后导入。

解压完成后提示解压的文件数量和目标目录，并说明：**包内若是 FBX、贴图等源文件，还需在 UE 中再次导入**。

::: warning 只能解 ZIP
其他格式会提示「应用只能解 ZIP。{格式} 请先用解压软件解开，再把文件夹导进资产库。」
:::

## 导入插件

资产右键有「**导入插件到项目**」，把库里的插件包装进目标工程。成功后提示「插件 {名称} 已导入到 {路径}」。

## 工程整包

把**整个 UE 工程**作为一个包上传和取回。入口在资产管理页右下角的上传按钮组，**只在当前库是资产服务器时出现**。

::: tip 为什么要有这条路
逐个文件传是一个文件一次请求，每次请求的固定开销和文件大小无关。一个五千到九千文件的工程，时间几乎全花在这笔开销上 —— 实测同一台服务器上，逐文件传一整天的量，打成一个包只要几分钟。数据通路本身不是瓶颈。
:::

### 上传

选一个或多个工程目录。它会：

1. **扫目录，跳过引擎缓存** —— `Intermediate`、`Saved`、`DerivedDataCache`、`.vs`、`.idea`、`.vscode`、`.git` 都不进包。**`Binaries` 保留。** 插件目录下同样按这个规则跳过。
2. **打成不压缩的 zip** —— UE 资产本来就是压缩过的，再压一遍只费 CPU。不落临时文件。
3. 传上去，得到一张 `<工程名>.zip` 的卡片。

多个工程**排队逐个传**（并发拿不到更多带宽，排队至少让第一个尽快传完）。

完成后报「{名称} 整包上传完成：N 个文件，{大小}，{速率} MB/s」。

::: warning 两件会在结果里说明的事

- **符号链接跳过**，并记进结果里告诉你。
- **空目录会保留**一条记录，否则取回时会凭空消失。

:::

直接选中一个现成的 `.zip / .rar / .7z` 也走这条路，不再打包，原样上传。

### 取回

资产右键「**取回工程整包…**」，选工程放到哪个目录。

下载时按服务器声明的字节数核对，**少一个字节都算失败**；解开时逐个文件核对字节数与校验值，越界路径直接拒绝。解完删掉压缩包，磁盘只占一份。完成后弹出资源管理器定位到工程目录。

两种结局：

- **已取回并解开到 {路径}**（N 个文件，下载 {速率} MB/s）—— 正常情况
- **已下载到 {路径}，请用解压软件解开** —— 盒子里没有 rar / 7z 的解包器，这两种格式只下载不解开

进度会显示当前阶段：扫描工程目录 → 打包上传 / 下载整包 → 解压。

## 导入进度与中断

进度挂件挂在应用这一层，切到别的页面照样看得见，也能从那里中止。

阶段包括：已处理 N/M、成功 N、已存在 N、失败 N。

### 上次没导完

再次进入时如果检测到「上次导入未完成」，会给两个选择：**继续导入** 或 **忽略**。

## 助手也能做这件事

也可以在 AI 会话中要求导入，例如「把素材库里那几个树的模型导到 XX 工程」。走的是同一套流程，出现版本冲突时同样会询问。

需要工程已连接，见[连接虚幻引擎](/guide/plugin)。
